View & Bus Protocol Map

4 addresses · 17-field viewport snapshot · 2 renderers · companion to Lesson 9

The server publishes one complete, viewport-bounded view to its renderers. This map covers the shared protocol, the browser's SockJS bridge, and the terminal's plain WebSocket transport.

The terminal endpoint is loopback-only. Its socket registers for published views and unregisters on close or exception. It adds no SockJS framing, heartbeat, or session identifier. The root launcher starts or reuses the server and starts the terminal client; ./gradlew run remains the server-only command.

Complete View Payload: 17 Fields

Produced by View.of(emc) and render(); rows are laid out by Viewport. Every field is present on every view.

Not in the payload: editorContent (whole document), ca (unused by renderer), and canvasStart/canvasEnd (replaced by origin and bounded rows).

Protocol obligations: every message is a complete viewport; ignore unknown fields; full:true discards cached rows; never re-wrap or re-order; clamp cursor coordinates; empty rows paints a blank screen. Since each update is complete, a dropped update costs a repaint, not a desynchronized patch.

Two Renderers, Shared Contract

  • Canvas: visur.js paints supplied row strings and projected cursor coordinates. It retains pixel metrics, font, canvas drawing and status-line presentation; it does not wrap text.
  • Terminal: protocol.rs decodes the same view; screen.rs composes the cell grid; paint.rs emits damage as row runs. keys.rs adapts terminal events; lifecycle.rs owns terminal lifecycle.

Viewport rows are cells, not pixels. The server owns wrapping and cursor projection; both renderers own only presentation and the screen they paint. The terminal subtracts its mode-line row from its declaration. The browser computes cells from pixel dimensions and declares its content grid.
