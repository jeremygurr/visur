View is not this. View.java declares two public fields (ca, editorContent) and no methods. The 15-field object above is constructed inline and View is never serialised. Any doc that lists the snapshot fields under "View" is describing toJson().

The Relay (why modelWasChanged reaches the browser)

  1. visur.js registers a handler on modelWasChanged (line 116); the bridge answers by registering a real local consumer for that address (EventBusBridgeImpl:243).
  2. Now two local handlers exist on modelWasChanged: ModelWasChangedVerticle and the bridge.
  3. bus.send(…) is point-to-point and picks one round-robin (EventBusImpl:353–390).
  4. If the bridge wins, the browser's handler re-sends the same address (visur.js:116–119), and the message re-enters the server — eventually landing on the verticle.
  5. So the snapshot may take a browser round trip before the repaint. The outbound modelWasChanged permission in MainVerticle:46 exists only to legalise step 1.

Framework behaviour verified against Vert.x 4.4.4 source. That the relay was written as a relay is inferred, not proven; ask the author.

Gotchas

  • No publish anywhere. Every message is send. "Broadcast" appears in the itinerary and wiki, not in the code.
  • Every keystroke ends in modelWasChanged, even an unbound key. The client is a pure function of the last payload.
  • Command state bypasses the keymap entirely. When isInCommandState, the key goes to commandStateService.executeCommandState instead (KeyWasPressedVerticle.java:19–21).
  • No window-resize handling. The canvas is sized once (visur.js:13–19) and canvasWasChanged is sent once (line 120); there is no resize listener.
  • Two canvasWidths. Client: floor(canvas.width / cellWidth) (visur.js:29). Server: (canvas.width − 6) / cellWidth + 1 as int (lines 110–113 → CanvasWasChangedVerticle:15–21). The payload never carries it, and the client never sends its own.
  • nl is newline-only. updateNextLineIndices looks only for '\n' (EditorContentService.java:86–101); wrapping is applied later by RelativeLineBoundCalculator using canvasWidth. The client re-implements that wrap with x % canvasWidth.
  • browser_input_service-proxy.js is unused. The generated BrowserInputService proxy sits next to visur.js but nothing loads it; the client talks to the bus directly.
  • frontEnd/editingScreen.js is not this frontend. It is a standalone prototype (hardcoded paragraph, local h/j/k/l, no EventBus). Useful as a contrast, not as documentation.
