Data Class Map

Two parallel trees · one hinge (requiredSetValues) · two conflict rules · companion to Lesson 7

Schema classes describe types; brick classes are the instances. A brick knows its schema, its name, and every container that holds it (outers). Containers declare how many children must be set. Setting a value walks the outers and removes anything that would overfill a container. This page is the compressed map.

Gotchas

  • LayeredDataClassBrick.isEmpty() always returns false—"empty" is not a uniform predicate.
  • LayeredDataClass.calcInternal keeps the last layer's result, not the first successful one (no break).
  • LayeredDataClassBrick.calc passes itself to a CompoundDataClass.calcInternal that casts to CompoundDataClassBrick—latent ClassCastException, currently unreached.
  • CAAndNLDC/CXCYAndNLDC calcInternal return null. The real math is on CoordinatesDC.
  • Forms validate but do not convert: concrete convertTo/convertFrom return null; canConvertTo short-circuits after the first array entry.
  • Completion is lazy, not enforced on build. An inconsistent graph is caught on the next put.
  • calcNeighbor only re-derives neighbors with outers.size() > 1—solitary neighbors are assumed to have nothing to re-derive.
  • Read-only bricks survive conflict removal because remove() is a no-op for them (nl relies on this).
