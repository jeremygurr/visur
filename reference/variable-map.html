What Reaches the Renderers

The map itself never crosses the wire. View.of projects values into the shared, complete 17-field viewport payload; Viewport lays out document text as bounded rows. Neither renderer receives ca, editorContent, or the VariableMap.

Gotchas Worth Remembering

  • VisurVar.make() is a static stub returning null (VisurVar.java:9–11). Never call it; the concrete make factories are the real ones.
  • ObjectVisurVar.putVal returns null while BrickVisurVar.putVal returns Result.make() (ObjectVisurVar.java:20–24). No caller reads it.
  • AssignmentOp has an unexercised BrickVisurVar branch that casts getVal() (a raw value) to PrimitiveDataClassBrick (AssignmentOp.java:21–22). No keymap assigns from a brick variable, so the branch never runs — assigning "nl" or "ca" would throw.
  • putCA re-puts the same mutated BrickVisurVar object back into the map; the second write is redundant but harmless (EditorModelCoupler.java:200–204).
  • The i sentence leaves one "character" on the execution-data stack because QuantumStartOp ignores the stack (QuantumStartOp.java:8–13).
  • nl is read-only (makeBrick("nl", new ArrayList<>(), true)): the true argument is isReadOnly, which stops a coordinate write from clearing it (PrimitiveDataClassBrick.put:80–88).
