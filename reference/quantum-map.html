Quantum Map

A boundary strategy, not a region · 4 registered quantums, 3 roles, 2 maps · companion to Lesson 6

A Quantum computes a region; it does not store one. The region lives in the model as cursorQuantumStart, cursorQuantumEnd, and span. This page is the compressed map of the strategy, the four implementations, and the operators that read them.

The Contract

MethodPurpose
getBoundaries(ca, nl, span, includeTail) Return {start, end} for the region around ca
move(content, nl, mv) Return the new absolute cursor position after a movement vector
getName() Return the registry name (character, word, …)

Gotchas

  • The registered name is word, not regex. RegexQuantum is a class; the instance is keyed "word" and is the only regex-backed quantum.
  • Search does not use RegexQuantum. It uses the scope quantum plus a literal indexOf.
  • includeTail is dead. Always false, never read.
  • getBoundaries has side effects. RegexQuantum writes ca; DocumentQuantum can reset span and move ca to 0.
  • LineQuantum.getBoundaries inlines its own arithmetic. It does not call RelativeLineBoundCalculator; only its move path does.
  • The declaration comment is stale. It says newline indices are "only needed in CustomQuantums", but LineQuantum reads them.
  • Bounds are half-open. A character at index 3 is {3,4}; the last two elements of a document are {0, length}.
