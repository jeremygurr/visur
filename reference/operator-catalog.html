Operator Catalog

Every editing action in Visur · 27 operators · companion to Lesson 4

An operator is a class implementing Operator.execute(Object opInfo). Operands come in on the ExecutionDataStack; side effects go out to the EditorModelCoupler. Read any operator with three questions:

  1. Stack in — pops? how many, in what order? peek? nothing?
  2. opInfo — does it use the compiler's operand, or ignore it?
  3. Model out — which emc.put…() methods does it call?

Gotchas

  • Pop order — RelativeMoveOp: pops dy then dx, so commands push (dx, dy). h is -1 0 relativeMove.
  • Pop order — AssignmentOp: pops the destination first, so "src" "dst" -> copies src into dst.
  • AbsoluteMoveOp is an empty stub despite being a registered keyword.
  • AddOperator is integer addition on the stack—not variable addition.
  • OperatorService / ModeSwitchService is dead: its only implementation does nothing and is never called.
  • "replace" is a submode, not an EditorMode. getModeByString("replace") returns null.
  • QuantumStartOp / QuantumEndOp hide a pop inside Quantum.getScopeAndCursorQuantums().
  • ChangeModeOp peeks, then delegates; PushSubmodeOp pops the same string as a submode name.
  • ChangeCursorQuantumOp can NPE if the top stack value is neither a known quantum name nor an existing global var.
  • Document-changing operators do not move the cursor; the mode handlers append 1 0 relativeMove.
